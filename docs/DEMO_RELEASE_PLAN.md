# 可上線 Demo 與後續模型／劇情計畫

這份計畫以「先做出可重複展示、可離線退化、可維護的完整遊戲」為目標。公開部署不在本階段範圍；校機 GPU 仍只允許 loopback 與 SSH tunnel，不直接暴露到網際網路。

## Demo 完成定義

- 乾淨環境可依文件啟動前端、後端與資料庫；缺少 GPU 時仍可使用規則式劇情走完主線。
- 六位地圖 NPC、艾倫通訊、維塔三問與五種結局都有可重播的正式 API 流程。
- 模型逾時、格式錯誤或路由缺失時，不會改壞場景、道具、故事節點或存檔。
- 每個玩家動作都有 loading、錯誤與重試狀態；重新整理後可承接已提交回合。
- 前後端契約測試、故事流程測試、Next.js production build 與八條 LoRA 健康檢查全數通過。
- Demo 使用固定版本的場景與人物素材，不在遊玩時即時生成必要資產。

## 實作順序

### P0：穩定性與可交付性

1. 建立單一 Demo 啟動與驗收入口，檢查環境變數、資料庫 migration、後端 ready、前端 build 與模型可選狀態。
2. 為模型失聯、回合衝突、存檔失敗及場景資產缺失補齊玩家可理解的錯誤與恢復路徑。
3. 將五結局流程、六位地圖 NPC 對話及八路由健康檢查固定為 release gate。
4. 產生不含 prompt／私密角色資料的 request ID、路由、延遲、重試與錯誤碼紀錄。

### P1：角色反應與簡單動畫

1. 保留後端 `DialogueLine.emotion` 為語意輸出，前端只映射到有限反應：平靜、專注、沉思、戒備、堅定、震驚、驚恐。
2. Phaser 角色只播放受控 tween，不接受模型輸出的座標、位移距離或任意動畫名稱。
3. 對話肖像與地圖角色共用同一反應映射，並支援 `prefers-reduced-motion`。
4. 先使用既有人物圖完成位移、後仰、震動、縮放與色調變化；之後若加入表情立繪，使用 `npc_id + reaction` 的資產 manifest，不把條件散落在頁面元件。

### P2：故事線與人物變化

1. 每個故事節點定義合法選項、回應角色、情緒、公開線索與下一節點；狀態變更仍由後端規則核准。
2. 為每位 NPC 增加三類無狀態對話：首次見面、承接前文、對關鍵玩家回答的情緒反應。
3. 需要持續影響後續劇情的關係或心情，先新增後端可驗證的公開狀態；模型只能讀取，不能直接寫入。
4. 每新增一段劇情，同時補「可走通、不可越級、重送不重複、重啟可恢復」四類測試。

## LoRA 訓練與評測方向

1. **凍結基準**：保留目前八角色多次抽樣、原始 LoRA probe 與 Gateway 守門後評測；兩種分數分開報告。
2. **清理資料契約**：以現有 3,437 筆資料／3,474 個 assistant 目標的標準化副本為起點，全部輸出 `ModelStoryOutput`，人格資料的 `event_proposals` 固定為空。
3. **補反應資料**：只使用有限 emotion 標籤；每位角色補齊一般、戒備、震驚、驚恐與沉思情境，避免只學到單一語氣。
4. **避免資料洩漏**：以完整對話／情境來源分組切 train、validation、test，不把同一段改寫拆到不同資料集。
5. **小規模消融**：先選兩位資料品質較完整的 NPC，比較 rank 8／16、2／4 epochs 與較低 learning rate；一次只改一項，再決定是否擴到八位。
6. **固定驗收門檻**：JSON／Pydantic 合格率、角色身分、公開知識邊界、繁體中文、emotion 合法率、延遲與拒絕率都需分項報告；不得用 Gateway 前置回答掩蓋原始 LoRA 退步。
7. **人工盲測**：由未參與資料編寫的人比較舊／新權重，至少檢查角色一致性、重複台詞、秘密洩漏、玩家指令注入與情緒是否符合語境。

## 維護原則

- API schema、故事規則、角色內容、動畫映射與 Phaser 呈現分層，不在 React 頁面解析台詞關鍵字來決定世界狀態。
- 所有模型可控制欄位使用 allowlist；未知 emotion 安全退回平靜，不執行任意動作。
- 劇情內容採資料定義，流程核准集中在 resolver；新增角色或反應不複製一套平行邏輯。
- 訓練資料、權重、評測結果與 runtime 版本都有固定 hash／版本，不覆寫既有基準。

## 部署與網域

自訂網域不是 Demo 的必要條件。可先使用部署平台提供的 HTTPS 網址，或在受控網路使用 IP／tunnel；但麥克風等瀏覽器能力通常需要 HTTPS 或 localhost。正式公開前再決定網域，並將前端與 API 放在同一站點反向代理，或明確設定 CORS、Cookie、TLS 與 rate limit。校機 GPU 依現行政策不可直接公開，需保留私有 Gateway 或改用獲准的推論服務。
