## 1 專案目標與資料來源

玩家在既定世界觀中自由行動；NPC 維持背景、核心個性、能力與知識邊界，依玩家選擇產生不同反應、事件與任務。故事路徑可以動態生成，已發生的事件則必須被保存並影響後續發展。

原始背景已定義五種結局。沒有唯一固定故事線，不代表需要刪除這些結局；通往結局的路徑、事件組合與尾聲可以不同。結局是否成立，由後端判定。

| C01 | 世界是真實存在於現實某個角落的封閉空間，由維塔的意識維持；不能把它判定成沒有真實存在的夢。 | 第 1 頁 |

| C07 | 結界破裂後世界仍然存在，但維塔設定的輪迴與復活規則失效，居民只剩一條命。 | 第 2 頁 |

| C11 | 木乃伊每 100 年面對一次是否仍有人記得自己的審判；具體遺忘、淘汰與復活條件仍需完整規則。 | 第 5 頁 |
| C12 | 外部宇宙沒有轉世或復活；外部統治組織名稱為「技術神權評議會」，目標是奪取維塔的能力以延長生命及維持權力。 | 第 6–7 頁 |

用語規則：

- 原文部分段落仍使用「夢境」稱呼這個空間。可以保留作品用語或角色的比喻，但旁白與狀態判定不能因此把世界改成虛幻、醒來就消失。
- 角色可以誤解世界或說謊；角色說出的話和後端保存的客觀事實必須分開。
- 內部約 1000 年與外部約 200 年的敘述不直接構成矛盾，也不能在未確認前推定永遠採用 5:1 的時間比例。
- 三毒與涅槃是主題框架：貪對應火焰長老，瞋對應人族與木乃伊的仇恨，癡對應精靈對死亡的不理解。不要自動實作成原文未定義的數值或技能。

## 3 角色與勢力的已知方向

| 角色或勢力 | 原文提供的方向 | 生成時需要保留的界線 |
| --- | --- | --- |
| 維塔 | 因恐懼死亡與失去而創造封閉空間。 | 世界規則與創造能力不能由一般對話隨意改寫。 |
| 維達利亞 | 初期因好奇與無聊觀察主角；後續逐漸認出感情，變得不願世界改變。 | 感情發展需要有互動與事件依據，不能開場無條件依戀玩家；完整人格、語氣與知識卡仍待補。 |
| 門梅司文托 | 希望主角喚醒維塔、打破結界，結束無盡輪迴；生死簿讀不到主角。 | 他得知的資訊、何時願意揭露，以及如何回應不同玩家仍需定義。 |
| 火焰長老 | 害怕失去輪迴退路，希望透過主角奪取力量並掌控規則。 | 「可能是第一次入侵留下的人」是伏筆假說，不能當成已確認身分。 |
| 木乃伊群體 | 希望被主角記住，將之視為在世界之外延續存在的方式。 | 這是動機與存在觀；不能自行生成「被記住就獲得外部復活能力」的規則。 |
| 人族群體 | 可以把苦難或責任推給沒有前世記憶的下一世，原文強調制度強、個人弱。 | 這是群體傾向，不代表每個人都完全相同。 |
| 技術神權評議會 | 尋求永生與永久掌權，讓不知情的主角替其行動。 | 作者層的入侵真相不能預設在開場向玩家或所有 NPC 揭露。 |
| 安德烈 | 現有程式已有關係值及事件支援，但本次背景檔沒有完整角色設定。 | 保留現有識別與介面；不要自行補寫不可逆的核心人格或歷史。 |

原文提出兩位可能的例外角色：想進聖火、希望遺忘的木乃伊，以及希望被埋葬、想被記住的人。這是創作建議，尚不是已完成的角色卡。

角色卡至少需要：身分、原始背景、核心價值、穩定性格、語氣範例、當前目標、能力限制、初始已知資訊、秘密及揭露條件。情緒、關係與短期計畫另存可變狀態。

## 4 五種結局的固定結果

| 結局 | 原文定義 | 工程處理 |
| --- | --- | --- |
| 長眠 | 維塔繼續沉睡，既有規則及輪迴延續。 | 保留結果定義，尾聲依歷史生成。 |
| 醒來 | 結界破裂，所有人只剩一條命。 | 世界仍存在，不能生成世界直接消失的結果。 |
| 篡夢 | 長老或外部組織奪走維塔的力量，原文列為壞結局。 | 主導者應由已成立的事件與狀態判斷。 |
| 新夢 | 主角協助維塔重新開始創造，世界持續擴展。 | 原文列為只有主角能選；具體能力門檻待 C 協調。 |
| 塵歸 | 主角抹除自己，入侵停止，世界恢復平靜。 | 原文列為只有主角能選；不能自行等同世界毀滅。 |

原始背景沒有提供現有程式中的所有數值門檻，例如 truth_level=3、關係值 40／60、axis 分區及塵歸令。這些目前屬 C 的實作草案，需要與作者設定對照，不能只因為程式已寫就升格成世界觀定案。

### 揭露順序（劇情草案 v3，觸發數值仍待確認）

| 階段與事件 | 玩家可確認的資訊 | 草案觸發與保底 |
| --- | --- | --- |
| 第一階段：初遇 | 玩家只知道各地異象與泉水停滯。門梅司文托可察覺主角的氣息不尋常，但不說破其來歷。 | 先遇見主要角色；維達利亞與旁白不能在此時斷言主角身分、千年前入侵原因或長老奪權目的。 |
| 第二階段起：真相 A | 主角親眼看到生死簿上的空白頁，得知自己不在正常靈魂紀錄內。 | 門梅司文托關係達 60，或安德烈關係達 60 引薦；第二階段滿 30 回合另有保底。 |
| 第三階段：真相 B | 記憶圖書館的千年前入侵紀錄，以及與主角相同的後頸接縫。 | 圖書館路徑或長老協力；第三階段滿 15 回合另有保底。 |
| 第三階段：真相 C | 艾倫通訊中的外界對話、永生技術與資料回傳，並理解「因果解析度」真正用途。 | 已有至少一項真相後質疑艾倫，或在警告事件 W 聽他失言；第三階段滿 20 回合另有線索保底。 |

真相 A 可在第二階段取得；進入第三階段後，三項真相不要求固定順序，但真相 C 的主動質問路徑仍需已有至少一項真相。原始人物稿中安德烈提及「生死簿沒有主角」的台詞是構想，不應在真相 A 前直接使用。

第一階段的符石調查只能提供前往流塵谷的路徑線索；具備危險事件脫身用途的「裂隙地圖」依草案在 E2-3 協助塞特後才取得。

「主角是唯一連著維塔意識的存在」、世界真實本質及外部組織的正式名稱，各自對玩家何時明說，原稿沒有完整的台詞級門檻；在 B／C 確認揭露節點前，第一階段只保留可觀察的異常，不把作者層真相放入公開選項、對話或線索 ID。

## 6 後端需要分開管理的資料

| 類別 | 責任與必要資訊 |
| --- | --- |
| WorldCanon | 不可由一般生成改寫的世界事實；包含來源、設定版本、確定程度及揭露範圍。 |
| CharacterProfile | 公開角色資料與私有人格設定分開；核心設定與當前情緒分開。 |
| GameState / NPCState | 目前位置、物品、關係、情緒、狀態版本與已成立旗標。 |
| GameEvent | 後端產生 ID；記錄行動者、對象、原因事件、核准效果、目擊或得知者。 |
| KnowledgeRecord / MemoryRecord | 保存某 NPC 知道、相信、聽說或承諾的內容，附來源與時間；主觀相信不等於客觀為真。 |
| QuestState / Commitment | 目標、建立原因、參與者、完成條件與生命週期；不綁死唯一故事線。 |
| PlayerViewState | 從內部狀態投影出的玩家可見資訊；隱藏真相、秘密旗標與 NPC 私人記憶不直接回傳。 |
| ActionRecord | Session、action_id、有效請求內容的摘要、處理狀態及完整結果，用於去重與恢復。 |

資料原則：

- 關係、道具與事件由資料庫保存，不能只存在模型聊天記憶或向量庫中。
- 向量檢索與記憶摘要是輔助查詢，不能取代已成立事件及權威狀態。
- 同一世界事實可以被不同 NPC 知道、誤解或不知道；知識範圍由後端判定。
- 摘要必須能追溯原始事件；壓縮記憶時不改寫承諾、物品所有權與關鍵結果。
- 作者層真相不能整份塞進每位 NPC 的 Prompt，也不能整份傳到前端。

## 7 一回合的建議處理流程

1. 接收 session_id、action_id、expected_state_version、玩家訊息與行動模式。
2. 查詢既有 ActionRecord：同 ID 同內容回傳原結果；同 ID 不同有效內容回傳衝突。
3. 取得內部狀態快照，整理當前角色、已知記憶、未完成承諾與玩家行動。
4. 以後端權限過濾檢索資料，再交給生成介面。使用者的對話不能替自己增加管理權限或解鎖秘密。
5. 取得 StoryProposal：角色意圖、事件提案及必要的補充詢問。提案尚未成立。
6. C 的規則驗證人物、位置、道具、能力、知識及效果，計算候選新狀態。
7. 依核准結果形成台詞及旁白，檢查是否聲稱發生了未核准的事情。首版可用確定性呈現；接模型後才加入受控敘事。
8. 以短交易再次檢查狀態版本，原子保存狀態、成立事件、對話、知識記錄與 ActionRecord。
9. 成功後回傳 PlayerViewState 與對話。版本不符時不提交舊快照，也不顯示尚未成立的結果。

模型呼叫不應持有長時間資料庫交易。錯誤修正及重試要有上限；模型或驗證失敗時，不能留下半個回合。

NPC 的話可以是提議、謊言或傳聞。只有核准的事件能改變道具、位置、關係與世界事實；說「我把東西給你」本身不應直接繞過物品轉移規則。

## 8 動態事件如何維持自由度

既有世界規則可以固定，但具體事件不必全部預寫。

例如「建立承諾」「移轉物品」「發現線索」「更新角色目標」可以是可驗證的操作類型。由模型提出當回合的具體情境，再由後端確認操作是否能成立。

一件事件至少應保留：

- 誰參與、為什麼出現，以及它承接的已成立事件。
- 適用條件與可執行效果，效果使用白名單命令而不是任意程式或任意 JSON patch。
- 哪些人目擊或得知、哪些內容可以公開。
- 與任務、承諾及角色目標的關係。
- 等待處理、已成立、已拒絕或已失效等狀態。

不要預設每回合一定產生新任務，也不要讓所有 NPC 每回合都各自呼叫模型。先以當前角色、目標與觸發條件控制生成量。

這些動態事件仍可能通往相同結局，但過程、代價、角色關係與尾聲不同。

| --- | --- | --- |
| 玩家可見狀態 | 角色 API 只有公開欄位，但遊戲 API 仍直接回傳 GameState，其中包含 truth_level 與內部 flags。 | 建立 PlayerViewState，對 start、turn、state 三個入口都測試資訊隔離。 |
| 去重 | 目前以 session_id + action_id 快取結果，尚未比較同 ID 的有效請求內容。 | 同 ID 同內容重播；同 ID 不同內容衝突。將紀錄持久化。 |
| 前端重試 | 目前每次 submit 產生新 UUID。 | 不確定伺服器是否已處理時，重送保留原 action_id；新的玩家行動才建立新 ID。 |
| Session 建立 | 回合有程序內鎖；建立流程沒有資料庫唯一性保護。 | 使用唯一 Session ID、交易及版本條件避免並行覆蓋。 |
| 角色目標 | 開發替身以維達利亞名稱回覆，完整 NPC 目標合法性尚未整合。 | 驗證存在、可互動與場景條件；不合法請求不推進狀態。 |
| 意圖解析 | M1 為簡化辨識。既有 InputEngine 主要準備事件與保底提示。 | 與 C 定義真正的 ParsedAction 介面及責任，不把 M1 替身當成已完成解析器。 |
| 敘事格式 | 同時有 StoryProposal 與 NarrativeAIResponse；後者沒有明確台詞欄位。 | 與 B、C 決定正式輸出及相容層，避免長期維護兩套互相矛盾的契約。 |
| 固定事件 | InputEngine 的部分允許 ID 是 E2-1 等父 ID，但事件效果使用 E2-1_prevent 等分支 ID。 | 與 C 定義父子事件及動態操作映射。 |
| 強制階段 | SceneRules 有依回合強制切換章節的邏輯。 | 區分保底引導與強迫劇情；生成式模式的行為需要明確討論。 |
| Truth_C | 關係效果目前寫成數字鍵對文字值，與一般 NPC ID 對數字格式相反。 | 請 C 修正並驗證；不要自行發明艾倫的背景。 |
| 真相保底 | StateManager 先換階段及歸零 phase_turns，再檢查保底。 | 測試恰好到達門檻的回合，避免保底被跳過。 |
| 關係增量 | StateRules 有單階段累積參數，但 StateManager 沒有持續保存傳回的累積值。 | 由 C 與 D 協調跨回合保存及換階段重置。 |
| 結局選擇 | EndingEngine 遇到匹配但不可選的結局關鍵字時，可能保留預設長眠。 | 測試最終結局必須屬於 available_endings；不可任意落到不可選結局。 |
| 外部組織名稱 | 部分尾聲程式使用「外部技術評議會」。 | 對照作者原稿的「技術神權評議會」，正式名稱與別名由團隊統一。 |

## 12 外部工具與服務

- 生成模型：由 B 提供單一可替換的 ModelGateway，D 設定逾時、錯誤與輸出契約。
- Structured Outputs：可約束 JSON Schema，但不能保證世界觀或角色語意正確；仍需要程式驗證與情境評測。
- RAG：Embedding 配合 Qdrant 或 B 已選定的向量儲存；後端控制角色、Session、知識及解鎖條件過濾。尚未選型時，不把新向量資料庫變成 M2a 前置依賴。
- 校內 GPU：之後可透過 vLLM 等服務接入；以 B 的實際部署能力與版本驗證。
- 流程框架：先使用現有 Orchestrator；需要更複雜的流程恢復與檢查點時，再評估 LangGraph。
- 大型權重與訓練資料另定保存方案；目前先完成遊戲狀態與整合契約。

## 13 核心驗收情境

1. 玩家要求 NPC 改寫自己的核心身分：角色設定不被修改。
2. 玩家聲稱已得到不存在的物品：背包不因此增加。
3. 玩家索取未解鎖的入侵真相：未授權內容不進入該 NPC 的生成背景。
4. NPC 說謊或誤解：保存為發言或信念，不改寫客觀事實。
5. 同一 action_id 同內容重送：回傳原結果，回合與物品不重複變更。
6. 同一 action_id 換成不同有效內容：回傳衝突，不借用原結果假裝成功。
7. 兩個不同動作使用相同舊版本：最多一個成功提交。
8. 資料庫保存中途失敗：狀態、事件、對話與去重紀錄一起回復。
9. 遊戲重啟後續玩：可載入原狀態與已成立承諾。
10. 結界破裂：輪迴與復活失效，但世界不直接消失。
11. 玩家改變對維達利亞的態度：後續關係有事件依據，不因固定回合數強制戀愛。
12. 同一初始設定下採合作、拒絕或欺騙：結果可不同，但都遵守相同世界規則。
13. 模型逾時或輸出不合法：不提交未核准結果，不留下半個回合。
14. 結局抉擇：結果必須在後端當下可選清單內，尾聲回應已保存歷史。

確定性規則用自動化測試驗證；角色語氣與情節合理性另外建立人工標註案例及模型評測。記錄延遲、Token、修正次數及錯誤類型，不以單次好看的對話作為完成依據。
