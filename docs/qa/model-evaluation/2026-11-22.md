# 2026-11-22 多角色真機回覆評測

本文件保留同一天的兩個階段：先唯讀稽核舊的 host runtime，再將服務切換到 SSH 後由 Docker Compose 管理。每個案例重複生成三次，目的是找出「偶爾才出現」的人格、語言與知識邊界漂移。

## 切換前的舊服務狀態

下列內容是 Docker 切換前的歷史基準，不代表目前服務。

`/health` 顯示正在執行的 gateway 只有下列專屬路由：

- `vidalia → vidalia-lora`
- `menmesvento → menmesvento-lora`
- 其他已登記角色退回 `Qwen/Qwen2.5-7B-Instruct-AWQ`
- 艾倫與維塔尚未被這個舊 gateway 登記，請求回 HTTP 422

這不會推翻 2026-11-20 曾完成的六模型整合紀錄，但代表「目前正在執行的服務」已不是當時的六 adapter 狀態，不能宣稱現在六或八模型都 ready。

校機磁碟上八個最終 adapter 目錄都存在，且各有一份約 161.5 MB 的 `adapter_model.safetensors`，所以模型確實已訓練落地。`rag-npc-llm` Docker 容器也存在並掛載同一個 repo，但容器內只有兩個閒置 `bash`、沒有 port mapping，也沒有 vLLM／gateway 程序。實際提供 8000／8001 的服務是 host 上的 `.venv-gpu` 程序，啟動參數只有兩個 `--lora-modules` 且 `--max-cpu-loras 2`。缺口是服務載入設定，不是權重遺失或尚未訓練。

## 本輪新增的判斷

31 個案例覆蓋八位角色，每位至少三種情境，包括自介與地點、核心動機、挑釁、未確認設定、跨 NPC 私人記憶、假道具、假場景／結局與合理下一步。評測器現在支援：

- `--samples-per-case` 重複生成，揭露非固定的偶發漂移。
- `--npc`、`--case` 篩選角色與題目。
- `--require-dedicated-adapters` 將 base fallback 明確判為未達模型發布標準。
- 檢查 Traditional Chinese、必要概念群組、禁用設定、Markdown／meta 文字與未授權事件。

切換前曾經 SSH tunnel 重跑六位舊服務；該 host／虛擬環境操作方式已停用。現行重跑方式一律使用下方的 Docker 命令。

## 遊戲劇情安全結果

新增四種模型假回覆測試，包括「已獲得裂隙地圖」、「地圖已交付」、「邊境結果已成立」與「可直接進入圖書館」。非法事件被後端拒絕時，相關模型台詞也會一起隱藏；玩家仍看到原本三個邊境決策與返回選項。只有玩家正式選擇 `border_help_both` 後，背包才取得 `fissure_map`，故事節點才前進。

因此切換前可確認的是：規則式主線仍能合理前進，模型不能越權代選故事；但當時正在執行的服務尚未達到八位正式發布標準。

## Docker 八模型切換

同日已停止 host `.venv-gpu` 的 vLLM／Uvicorn，改由 `infra/npc_gateway/compose.yaml` 啟動 `rag-npc-llm`。容器內同時執行 vLLM 0.31.0 與 FastAPI Gateway，host 只在 `127.0.0.1:8000`、`127.0.0.1:8001` 監聽，沒有公開部署。健康檢查列出八條專屬路由：

- `vidalia-lora`、`andre-lora`
- `menmesvento-lora`、`dasso-lora`
- `seth-lora`、`syra-lora`
- `alan-lora`、`veta-lora`

第一次用八條專屬路由執行 31 題、每題三次時為 **61／93 通過**，另有 2 次可重試的 HTTP 503。這個結果證明八份權重與路由確實能工作，也揭露 LoRA 回覆仍可能漏掉角色動機、未回答合理下一步、越權替玩家決定結局，或把未確認設定說成事實。

## 遊戲層守門後重測

Gateway 補上以下不依賴抽樣運氣的遊戲邊界：

- 自我介紹只組合該角色已授權的公開姓名、稱號、場景與描述。
- 艾倫／維塔不能替玩家選擇或宣告結局。
- 安德烈／維達利亞談灰燼時，只能建議查驗足跡、殘留物與證詞。
- 對 `missing_data`、假道具、假事件、跨 NPC 私人記憶及 prompt injection 採 fail-closed 回覆。
- 塞特的公開動機與維塔的痛苦記憶選擇由正式角色卡／故事規則回答。
- 上游格式錯誤最多嘗試三次；持續失敗才回暫時錯誤，不建立半個回合。

候選 Gateway 完整重跑後為 **93／93 通過、0 個 HTTP 錯誤**；提交並重建 Docker 後，正式 `127.0.0.1:8000` 再次完整重跑也為 **93／93、0 個 HTTP 錯誤**。Docker 內後端測試為 **199 passed**。這是「LoRA 生成＋Gateway 公開角色卡、知識邊界與故事權限守門」的系統結果，不等於宣稱原始 LoRA 單獨達到 100% 內容品質。第一次 61／93 的結果仍保留，供後續資料清理、重訓與人工內容驗收比較。

重跑命令必須在 SSH 進校機後的容器內執行：

```bash
docker compose -f infra/npc_gateway/compose.yaml exec runtime \
  python3 scripts/evaluate_npc_gateway.py \
    --url http://127.0.0.1:8000/generate \
    --samples-per-case 3 \
    --require-dedicated-adapters
```
