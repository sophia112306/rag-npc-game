## 生成後的場景保護

1. [移除裝飾後的泉眼](02-protected-spring.jpg)：Tab 輸入「移除樹木，移除符石，移除祭壇」，三類數量均為 0，但固定泉池保留；W 前進停在實心地標外 3.5m，E 可調查「聆聽泉底裂響」，取得手記並解鎖流塵谷。固定地標不排入 GPU 重生工作。
2. [真實新 GLB 與固定泉眼並存](03-generated-scene.jpg)：輸入「生成 2 座祭壇，變成黃昏」。校內 Hunyuan3D-2mini 經既有 SSH tunnel 產出新祭壇，後端 `/model` 回應 200，Babylon 接受後顯示 1/1。裝飾使用新模型，主要泉池保持同一版本化模型及 x=0、z=-6、scale=6.8、yaw=.25；原有調查紀錄仍在。重整後模型與場景配置可恢復。
3. [下載失敗仍可探索](06-model-fallback.jpg)：Chrome CDP 暫時阻擋新模型的 `/scene-assets/*/model` 請求，畫面顯示「0 項載入；1 項保留既有模型」。仍可步行到泉邊並按 E，兩個調查選項正常。解除阻擋並重整後恢復 1/1，沒有因重試增加遊戲回合。
4. 視覺檢查修掉霧氣的大白色粒子與泉面靶心式水紋；泉眼改用與原版議會湖水共用的反射材質。裝飾移除後的空曠畫面是該指令的預期結果，並非森林預設配置。

自動驗證：123 個後端測試、11 個前端測試及 Next.js production build 通過。後端包含三個場景 × 40 個 seed 的核心地標保護；前端包含三軸尺寸、極薄／無效模型拒絕與實心地標外的互動距離。正常操作未觀察到阻斷性 JavaScript 例外。
